OneRec-V1解读
Swift Lv6

  • LLM
  

OneRec通过端到端的生成式框架替代了传统的召回-排序的级联架构。在此系统学习下OneRec-V1。

1. 背景与动机

传统推荐系统采用多阶段级联架构（召回 → 粗排 → 精排 → 重排），论文指出其三大根本性缺陷：

1.1 计算碎片化

以快手为例，服务期 超过 50% 的资源用于通信和存储而非高精度计算。精排模型在旗舰 GPU 上的 MFU 仅 4.6%（训练）/ 11.2%（推理），而 LLM 在 H100 上可达约 40%。同时 QPS > 400k、延迟 < 500ms 的约束，使模型被迫在低算力规模运行。

1.2 目标冲突

  • 多目标冲突：CTR、观看时长之外还有数百个来自用户、创作者、平台生态的目标，分散在各阶段优化，逐步破坏系统一致性；
  • 跨阶段建模冲突：召回效果受限于排序模型能力，排序又受上游次优结果影响。

1.3 落后于 AI 演进

LLM/VLM 领域的缩放定律、强化学习（RLHF/DPO/GRPO）等突破，因级联架构的结构性壁垒难以迁移到推荐场景。

1.4 OneRec 的解法

将召回与排序合并为单阶段 Encoder-Decoder 生成式框架，端到端直接优化最终目标，并严格优化训练/推理计算效率。

2. 整体架构

OneRec 是一个Encoder-Decoder生成模型：输入用户多尺度行为表示，自回归生成目标视频的语义 ID 序列。

3.4 奖励系统与 ECPO 强化学习

预训练模型只拟合曝光 item 分布（来自传统系统），无法突破传统推荐天花板。因此引入基于奖励系统的偏好对齐，在生成 item 空间做 on-policy RL。

3.4.1 偏好对齐：P-Score

关键改进动机：原 GRPO 对负优势允许大策略比，易梯度爆炸。ECPO 对负优势样本提前 clip 最大 ratio，保证训练稳定同时保留负优势效果；因 RL 与 SFT 联合训练，移除 KL 散度损失（SFT loss 保证稳定性）。

3.4.3 格式奖励（Generation Format Regularization）

挤压效应（Squeezing Effect）：加入 RL 后，负优势样本使模型把概率质量压缩到当前最优输出 $o^*$，导致合法 token 概率被挤到与非法 token 相当，合法率跌破 50%。

解法：从 $G$ 个样本随机选 $K$ 个做合法性 RL：

优化目标同 ECPO 公式，直接用 $A_i$ 作优势。实验显示 Top-k 选择会让模型只在 top 子集学合法（整体合法率先升后降），随机选择更稳健，最终达 95% 合法率，且带来 App 停留 +0.13%、观看时长 +0.30%。

FAQ

1. 每天大量产生的新视频如何冷启？

  • 论文中没有明确提出
  • 咨询了参与者，也没有针对该问题解决
  • 视频tokenize生成的sid具有一定的泛化性，相似的视频具有相同的前缀sid，对新品友好

2. 有无替代重排？如无替换，重排依赖的精排打分从何而来？

论文中没有明说，听内部人士说只替换了召回和粗排。

3. p-score是否来源于老汤模型推出的item，那天花板是否还是老汤模型？

是的。P-Score 训练样本来自老汤曝光日志，用户只对老汤推过的视频产生行为，label 是“老汤曝光分布下的真实偏好”。尽管在RL阶段，模型尝试生成多个候选item进行探索，突破现有RS的天花板，但对老汤从未曝光的 item 类型，P-Score 打分可能失准，RL 探索得再远，奖励信号本身仍带老汤烙印。

4. 预训练和RL训练的样本有何异同？曝光空间，还是点击空间

OneRec 的 RL 训练把探索空间从曝光空间扩展到了生成空间，但奖励信号仍然依赖基于老系统样本训练的 P-Score。因此它并不是完全摆脱老系统偏置，而是通过生成式探索 + 奖励模型 + 工业奖励，逐步突破老系统的分布天花板。

  • 预训练 + RSFT：样本来自曝光空间（老汤曝光的目标 item，RSFT 按播放时长取前 50%），NTP 拟合曝光分布，天花板 = 老汤；
  • RL：样本来自生成空间（策略模型自生成 G 个 item，G≈512~2048），P-Score 打分驱动 ECPO，设计上要跳出曝光空间，但受合法性、预训练概率、P-Score 曝光偏差三重约束，实际探索范围是“合法 SID 空间 ∩ 预训练高概率区 ∩ P-Score 可信区”的交集；
  • 两者都不是点击空间：点击/互动 label 只用于训练 P-Score 奖励模型，不直接作为预训练目标或 RL 样本；真正的点击反馈闭环只出现在线上 A/B 评估，不进入训练。

5. 对于特定的业务诉求, 如新冷内容扶持, 打压营销号，是如何支持的？

论文对业务诉求的支持统一收敛到”奖励系统 + RL”这一条路径——把业务目标翻译成奖励项，通过 ECPO 在生成空间做端到端优化，而不是像级联架构那样在某个阶段打补丁。

6. NTP为什么拟合的是曝光分布，而不是点击分布？

这一点“推荐核心是预估兴趣、拟合点击合理”在判别式排序范式下完全成立，OneRec 也确实用 P-Score 学了点击/互动——但它把这部分放在了“奖励模型”而非“NTP 目标”的位置。NTP 之所以拟合曝光而非点击，是因为生成式范式的任务是生成候选而非给候选打分：曝光序列是完整的消费序列，样本量大、含负反馈、覆盖“会看但不点”的高价值内容；点击序列稀疏、断裂、偏向短平快，撑不起生成式预训练，也与观看时长等核心指标矛盾。两者不是替代关系，而是分工：NTP 生成候选（拟合消费分布），P-Score 评估兴趣（拟合点击/互动），RM Selection 精选淘汰负 item。
